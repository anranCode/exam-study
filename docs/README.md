## 一、这个项目是什么

一个**纯自用**的自考备考工具:把历年真题录进系统,按遗忘曲线安排复习,用碎片时间刷题,并通过浏览器推送把你拉回学习状态。

不做多用户、不做社交、不做排行榜。唯一用户就是考生本人。

### 现实约束(决定了所有设计)

| 约束 | 说明 |
|---|---|
| 用户数 | 1(本人) |
| 使用设备 | 安卓手机为主,电脑为辅 |
| 部署 | 本机运行,不需要公网服务器 |
| 提醒 | **刚需**,必须能定时推送提醒学习 |
| 题库来源 | 自己录入真题(课本 + 试卷) |
| 目标 | 60 分及格,不是高分 |

## 三、给 Claude Code 的执行约定

1. **先读 `design/tech-stack.md`**,再读对应端的 `README.md` 与 `01-architecture.md`。
2. 按 `04-features.md` 的**阶段顺序**实现,每个阶段做完停止并等待确认,不要一口气写完所有功能。
3. 数据模型以 `backend/02-data-model.md` 为唯一准绳,前端字段名不得自行改名。
4. 接口以 `backend/03-api-spec.md` 为准,前端不得绕过封装直接拼 URL。
5. 遇到文档未覆盖的情况,**先提问,不要自行决定后继续**。
6. 每个阶段结束时必须满足该阶段列出的「验收标准」。

## 四、技术选型速览

| 层 | 选型 | 一句话理由 |
|---|---|---|
| 前端 | Vue 3 + Vite + TypeScript | 组合式 API 心智负担低;Vite 启动快;TS 让前后端字段对得上 |
| 前端状态 | Pinia | Vue 官方推荐,比 Vuex 简单 |
| 前端路由 | Vue Router 4 | 官方方案 |
| 前端 UI | Element Plus | 组件全、中文文档好,够用不折腾 |
| 前端 PWA | vite-plugin-pwa | 让手机能「添加到主屏幕」,并支持离线缓存 |
| 后端 | Java 17 + Spring Boot 3 | 用户主栈,企业主流,学习价值高 |
| 后端持久层 | Spring Data JPA + Flyway | 少写 SQL;Flyway 管版本化建表脚本 |
| 后端提醒 | 微信通道(企微机器人 / Server酱) | 服务端直调 Webhook,免 HTTPS 免备案,微信到达率高 |
| AI 辅导 | 通义千问(DashScope) | 复用已有 TokenPlan,后端调用、按需生成并缓存 |
| 部署 | 腾讯云轻量服务器 | 7×24 在线,提醒不依赖个人设备开机(至 2027 年 2 月) |
| 数据库 | MySQL 8 | 与 Spring Boot 组合最成熟 |
| 构建 | Maven + npm | 各自生态默认 |

详细的选型理由与取舍见 [`design/tech-stack.md`](design/tech-stack.md)。

## 五、技术选型中的两个关键决策

### 1. 为什么最终是 SPA + 后端,而不是纯原生安卓

最初考虑的是「纯本地原生 Kotlin App、无后端」,但既然明确需要**题库管理 + 定时推送 + 数据看板**三件事,后端能一次性解决:题库集中存储、复习排期在服务端计算、推送由服务端定时触发。前端做成 SPA 后,电脑上录题、手机上刷题用的是同一套代码。

### 2. 「提醒刚需」怎么实现

```
Spring Boot @Scheduled(每分钟,跑在腾讯云服务器上)
        ↓ 查询「到期复习题数」「今日是否已打卡」
微信通道(企业微信群机器人 / Server酱 Webhook)
        ↓ 服务端直调,即发即达
微信收到「今日 12 题待复习,其中《马原》5 题」+ 跳转链接
        ↓ 点开链接
直接进入复习页面
```

要点:服务器 7×24 在线,提醒不依赖你家里电脑是否开机;用的是微信消息而非浏览器通知,免 HTTPS、免域名备案,国产手机到达率高。

### 3. AI 老师怎么工作

后端调用通义千问(DashScope OpenAI 兼容接口),角色固定为「自考冲刺辅导老师」,输出遵循「点名考点 → 大白话讲对错 → 一句记忆提示 → 120 字以内」。四种能力:精简解析(刷题页「问老师」)、举一反三(错题生成变式题)、记忆口诀、考前串讲清单。**按需生成 + 结果缓存**,同一道题不重复消耗 token。
