# 前端功能实现清单

> 按阶段实现,**每个阶段做完停下来等确认**。
> 前端阶段与后端阶段对应:前端阶段 N 依赖后端阶段 N 完成。

---

## 阶段 0:工程骨架

**要做的事**

1. `npm create vite@latest frontend -- --template vue-ts`。
2. 装依赖:vue-router、pinia、element-plus、axios、echarts、vite-plugin-pwa、openapi-typescript、vue-tsc。
3. 配 `vite.config.ts`:别名 `@ → src`、dev server proxy(`/api → http://localhost:8080`)、PWA 插件。
4. 建目录结构(见 `01-architecture.md` 第一节),空文件可先占位。
5. `styles/variables.css` 把 `ui-design-spec.md` 的全部 CSS 变量写进去,`element-override.css` 覆盖 Element Plus 的主色。
6. 配 `main.ts`:注册 Pinia、Router、Element Plus、全局样式。
7. 实现 `api/request.ts` 的 axios 实例与拦截器。
8. `MobileLayout` / `DesktopLayout` + `useBreakpoint`,`App.vue` 按断点切换。
9. 一个 `NotFoundView`。

**验收标准**

- `npm run dev` 启动,页面显示底部 Tab(手机宽度)或左侧栏(桌面宽度),切换窗口宽度布局会跟着变。
- 访问不存在路径显示 404 页而不是白屏。
- 请求 `/api/v1/unknown` 时弹出统一的中文错误提示,而不是控制台报错。
- 所有颜色都来自 CSS 变量——在 `variables.css` 把主色改成红色,整站跟着变。

## 阶段 1:科目与今日页(骨架版)

**要做的事**

1. `SubjectListView`:科目列表 + 章节树的增删改,含取色器、考试场次下拉与**科目专属 AI 提示词**(答题语言 / 词汇难度 / 答案结构 / 解析长度等)。
2. `useSubjectStore`。
3. `TodayView` 的静态结构:日期、考试倒计时、连续天数卡片、主任务按钮、分科目列表(数据先写死,后端阶段 1 完成后接真实数据)。
4. `StatNumber`、`SubjectTag`、`ProgressBar`、`EmptyState` 四个通用组件。

**验收标准**

- 能新建/编辑/删除科目,颜色和场次能正确保存(调后端接口验证)。
- 手机宽度下今日页一屏能放下主任务按钮,不需要滚动才能看到。
- 主任务按钮是所有元素里最大的可点击区域。

## 阶段 2:题库管理

**要做的事**

1. `QuestionListView`:筛选栏(科目/章节/题型/年份/关键词)+ 表格 + 分页。
2. `QuestionEditView`:动态表单,题型切换时选项区与要点区互相显隐。
3. 正确答案用 Radio/Checkbox 点选,不手打字母。
4. 前端表单校验,错误定位到具体字段。
5. 删除二次确认。
6. 表格勾选 + 批量操作条:批量入库(待校对 → 已入库)、AI 生成答案/解析(全部题型,客观题只补空答案,可勾选覆盖已有解析)。
7. 编辑页解析旁提供「AI 生成」:按科目 + 题型生成具体答案与解析;客观题只补空答案,主观题先写答案(写作题给英文范文 + 译文)再写解析。
8. 科目表单支持配置该科目的 AI 提示词,生成时优先遵守。

**验收标准**

- 新建一道单选题:选了题型后自动出现 4 个选项输入框,答案区是 4 个 Radio。
- 新建一道简答题:选项区消失,出现「参考答案要点」可增删列表。
- 分值填 0 或负数时前端直接拦下,不发请求。
- 多选题答案点选 A、B、D 后保存,重新打开显示仍然勾选 A、B、D。
- 表格中题干超过两行时省略并显示 tooltip。
- 勾选几道「待校对」题点「批量入库」,状态变成「已入库」,练习抽题池能抽到它们。
- 给科目配「答案一律用英文」后生成英语写作题,得到英文范文 + 译文 + 解析;单选题生成后答案保持已有值、不会被 AI 覆盖。
- 勾选一道无解析的题点「AI 生成答案/解析」,内容被写入并能在编辑页看到;AI 未配置时提示失败且不影响列表。

## 阶段 3:批量导入 ★

**要做的事**

1. `QuestionImportView`:文件上传 + 文本粘贴两个入口。
2. 预览表格:每行显示题号、题型、题干摘要、校验状态;不合格行标红并显示原因。
3. 「跳过并继续导入」「返回修改」两个操作分支。
4. 导入结果卡片。
5. 右侧「导入格式说明」抽屉,含可复制的 JSON 示例。
6. 从前端本地校验 JSON 结构(至少判断 `items` 是否为数组),避免把明显错误的文件发到后端。

**验收标准**

- 上传一份合法 JSON,预览表显示 40 行全部通过,导入后提示「成功导入 40 题」。
- 上传一份第 12 题缺 `answer` 的 JSON,预览表第 12 行标红并写明原因,选择跳过后能成功导入其余 39 题。
- 上传一个非 JSON 文件(如 `.txt`),前端直接提示「文件不是合法的 JSON 格式」,不发请求。
- 导入完成后跳到题库列表,能立刻搜到新导入的题(需要清缓存或重新拉取)。

## 阶段 4:刷题 ★ 核心

**要做的事**

1. `OptionCard.vue`:五种状态(默认 / 选中 / 正确 / 错误 / 正确答案)。**不只用颜色区分,必须带 ✓ ✗ 图标。**
2. `QuestionCard.vue`:题型标签 + 题干 + 选项 + 解析区。
3. `usePracticeStore` + `useAnswerFlow` 完整答题状态机。
4. `PracticeView`:三段式布局,单选类点选项即判定;答对自动下一题、答错停留,底部在判定后给「下一题」;另有「不知道」。
5. 主观题分支:多行输入 + 「对照答案要点」+ 逐条勾选自评 + 提交自评。
6. `ResultView`:本轮小结。
7. 退出确认 + 进度恢复(localStorage)。
8. 答题进度逐题提交,失败的题不允许跳过(必须重试)。

**验收标准**

- 手机上单手握持时,底部操作按钮在拇指可及范围内(固定在底部)。
- 判定后选项不可再点;正确答案始终标绿,即使答对了也能看到其他选项的判定状态(阅读判断的 `NG` 也要正确高亮)。
- 答错时解析自动展开,不需要额外点击;答对后 1.2 秒自动进入下一题,也可提前手动点「下一题」。
- 点「不知道」提交后:立即看到正确答案与解析,该题出现在错题本里;主观题按 0 分自评。
- 答到第 8 题时关闭页面,重新打开能提示「还剩 4 题,继续?」并恢复到第 9 题。
- 断网状态下提交,提示提交失败且**停留在当前题**,不跳到下一题。
- 主观题勾选 3 个要点中的 2 个后提交,后端 `self_score = 2`,该题进入错题本。

## 阶段 5:错题本

**要做的事**

1. `WrongBookView`:按科目分组、筛选(科目 / 题型 / 是否到期 / 是否已掌握)。
2. 每条显示题干、错误次数、连续答对进度(x/3)、下次复习时间、掌握阶段。
3. 操作:立即复习(只做这一道)、标记已掌握、移出。
4. 顶部「今日到期 N 题」+「开始刷题」:按当前科目 / 题型从错题池随机抽题;勾「只看已到期」则走 REVIEW 只练到期题。
5. 连续答对 3 次自动移出错题本(切到「已掌握」仍可见,再答错会回到未掌握)。

**验收标准**

- 答错一题后,错题本立刻出现该题(不需要刷新页面);从未答错过的题不会出现在错题本里。
- 「标记已掌握」后该题从默认列表消失,切到「已掌握」筛选能看到。
- 选「马原 + 单项选择题」后点「开始刷题」,进入的练习只包含这两个条件下的错题。
- 同一道错题连续答对 3 次后,默认列表里不再出现,并给出「已移出错题本」提示。

## 阶段 6:统计看板

**要做的事**

1. `StatsView` 三块:大数字、科目正确率条形图、30 天趋势折线图、章节掌握度。
2. ECharts 按需引入(只引 BarChart、LineChart、对应组件),不要把整个 echarts 打进包。
3. 骨架屏加载态。

**验收标准**

- 无数据时显示空状态文案而不是空白图表。
- 趋势图缺数据的日期显示为 0 而不是断线。
- 图表颜色与科目色一致。
- 生产构建产物里 echarts 部分不超过 400KB(按需引入生效)。

## 阶段 7:设置与提醒(微信通道)★ 提醒刚需

**要做的事**

1. `SettingView`:学习设置、自由练习默认设置、提醒设置、通道配置四块。
2. `api/notify.ts`:`GET/PUT /settings`、`POST /notify/test`、`GET /notify/logs`。
3. 通道配置表单:通道选择(企业微信 / Server酱)、Webhook 或 SendKey 输入(保存后掩码回显,不显示全文)、「发送测试提醒」按钮与结果反馈。
4. 提醒日志查看区:近 7 天发送记录与失败原因。
5. 自由练习默认设置:默认题源(题库 / 错题)+ 两个题源各自的默认科目、题型、题量。
6. PWA manifest 与图标(192/512)。

**验收标准**

- 填入企业微信 Webhook 后点「发送测试提醒」,微信里收到消息。
- 刷新页面后,Webhook 输入框显示的是掩码(如 `…a1b2c3`),不回显完整值。
- 把 Webhook 改错后点测试,页面给出失败原因(来自后端 `reminder_log.fail_reason`)。
- 提醒日志区能显示每条提醒的日期、类型、成功/失败。
- 在设置里把题库默认设为「马原 + 单项选择题 + 10 题」,进入自由练习自动带入这些条件;错题题源同理。

## 阶段 8:打包与体验打磨

**要做的事**

1. `npm run build` → 产物拷到后端 `src/main/resources/static/`。
2. 确认 SPA 刷新不 404(配合后端 `SpaForwardController`)。
3. 手机端实测:添加到主屏幕、离线打开(Service Worker 缓存)、刷题、接收微信提醒全流程。
4. 骨架屏、loading 态、错误提示的文案统一检查一遍。
5. 检查所有空状态文案与 `02-routes-and-pages.md` 第四节一致。

**验收标准**

- 手机上「添加到主屏幕」后从桌面图标打开,是全屏无地址栏的独立窗口。
- 飞行模式下打开应用,今日页与题库能显示(Service Worker 缓存生效)。
- 全站搜不到 `alert(` / `confirm(`。
- 全站搜不到写死的十六进制颜色(除 `variables.css`)。
- 在任意路由刷新不 404。

## 阶段 9:AI 老师界面

**要做的事**

1. `components/AiDrawer.vue`:底部抽屉(手机)/ 侧边抽屉(桌面),展示 AI 回答;含加载骨架、「重新生成」按钮、失败重试。
2. 刷题页:判定后在解析区底部加「问 AI 老师」按钮;请求携带本题 ID 与用户错选,展示精简解析。
3. 错题本:每条错题提供「问老师」与「举一反三」;变式题用卡片展示题干、选项、答案,提供「做一遍」与「存入题库」。
4. 考前串讲页(`/digest`):按科目生成 / 查看「必背 N 点」清单,逐条勾选「已背会」,支持一键复制。
5. 统计页增加 AI 用量小卡(近 30 天 token 消耗,来自 `/ai/usage`)。
6. 所有 AI 请求失败(`code = 6001`)时降级:显示原解析 + 「重试」按钮,不阻塞练习流程。
7. 题库的「AI 生成解析」也走同一套 AI 配置:编辑页预览填入、列表批量生成保存;失败时只提示,不影响题库操作。

**验收标准**

- 刷题答错后点「问老师」,抽屉出现讲解;再点一次秒开(命中缓存)。
- 带错选的请求,讲解里能看到对用户所选选项的点名分析。
- 断网时点「问老师」,提示失败并可重试,刷题流程不受影响。
- 「举一反三」生成的变式题可一键存入题库,题库列表能搜到。
- 考前串讲生成后重新进入页面直接显示(已缓存),点「重新生成」才覆盖。

## 组件级验收清单(通用)

每个新组件写完后自检:

- [ ] 手机宽度(375px)下显示正常,无横向滚动
- [ ] 可点击元素最小 44×44px
- [ ] 颜色来自 CSS 变量
- [ ] 有 `:focus-visible` 焦点样式
- [ ] 数据为空时有合理显示(不出现 `undefined` / `NaN`)
- [ ] 长文本(超长题干、超长英文单词)不会撑破布局
- [ ] 加载中有骨架屏或局部 loading
